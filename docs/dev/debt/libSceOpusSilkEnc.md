# libSceOpusSilkEnc technical debt

### Unknown function info

- [sceOpusSilkEncCancel, sceOpusSilkEncCtl, sceOpusSilkEncEncodeFloatWithPriority, sceOpusSilkEncEncodeFloatWithPriorityAndTimeout, sceOpusSilkEncEncodeWithPriority and sceOpusSilkEncEncodeWithPriorityAndTimeout](../../../core/libs/prx/libSceOpusSilkEnc/Export.cpp) (libSceOpusSilkEnc) - names and NIDs are present in the [PS5 3.20 export inventory](https://github.com/DNNDHH/PS5-3.20_Libs/blob/b2a77c09cd71c01f34c790cfbe98c751a13262ad/libSceOpusSilkEnc.c). The prototypes mirror the sibling encoder declarations and libopus's own ctl and priority entry points, but the console's request codes, priority, timeout and batch-id semantics were not recovered. They throw through `NotImplemented_nid_no_patch`; this is not an ABI claim.

### Functional

- [libSceOpusSilkEnc](../../../core/libs/prx/libSceOpusSilkEnc/Export.cpp): the state layout behind [GetSize](../../../core/libs/prx/libSceOpusSilkEnc/Export.cpp) is only partially recovered from the [firmware 13.42 export measurements](https://github.com/boykopovar/AnyPS5/pull/10563#issuecomment-6401539314). A successful encode setup writes the 752-byte zero-fill and the 0x17B2 marker at +0xE8 into the state; the console's remaining setup bytes and whether its packets equal ours stay unknown. The console requires application 2048 (`OPUS_APPLICATION_VOIP`) and the library builds its encoder with the restricted silk application instead; that mapping is this implementation's choice, not recovered from the setup
- [Create, CreateEx, Destroy, GetSize and Initialize](../../../core/libs/prx/libSceOpusSilkEnc/Export.cpp) refusal codes follow the same measurement, base 0x81770000 with the offsets +0x01, +0x0F, +0x0C and +0x10 for null state or context, sample rate, channels and application, +0x15 for a wrong state marker in `Destroy` and +0x18 for `Initialize(nullptr)`; other firmware versions remain unverified. [Encode and EncodeFloat](../../../core/libs/prx/libSceOpusSilkEnc/Export.cpp) still validate with the offsets 0, 1, 6, 7, 8 and 9 that the recovered libSceOpusCeltDec validation suggests; the measurement did not cover them. `Terminate` throwing for live `CreateEx`, a zero-frame encode, a libopus rejection and `OPUS_ALLOC_FAIL` also throw as that analogue does. Closes when: a supplied PS5 module settles the state layout, the `Encode` validation and the console's packet equivalence
